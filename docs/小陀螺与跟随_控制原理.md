# 小陀螺直线行走 与 跟随模式 —— 控制原理

> 本文说明"小陀螺走直线"和"底盘跟随云台"两个功能的控制原理、数学推导、
> 三个控制环的分工，以及当前实现的缺口。

> ⚠️ **本文写于 A 板版本，控制原理与代码结构在 C 板上完全一样。**
> 文中提到的板载 IMU `MPU6500` 在 C 板上是 `BMI088`（SPI1，驱动 `user_bmi088.c/h`，
> 接口与 `attitude.c` 的用法一字未变）。板级引脚对照见 **[C板移植说明.md](C板移植说明.md)**。

## 一、符号与坐标系约定

### 坐标系（全部右手系，逆时针为正）

| 坐标系 | 定义 |
|---|---|
| **世界系** $(X, Y)$ | 场地固定，X 前、Y 左 |
| **车体系** $(x_b, y_b)$ | 跟着底盘转，$x_b$ 指向车头 |
| **云台系** $(x_g, y_g)$ | 跟着云台转，$x_g$ 指向云台前方 |

### 三个角度

| 符号 | 含义 | 谁来测 | 特性 |
|---|---|---|---|
| $\psi_c$ | **底盘**朝向（世界系中） | ❌ 没有直接测量 | — |
| $\psi_g$ | **云台**朝向（世界系中） | ✅ **板载 MPU6500**（yaw） | 绝对，但**会漂** |
| $\theta$ | **云台相对底盘**的角度 | ✅ **GM6020 绝对编码器** | 机械量，**不漂** |

### ⭐ 三者关系

$$\theta = \psi_g - \psi_c \qquad \Longleftrightarrow \qquad \psi_c = \psi_g - \theta$$

> **GM6020 的定子装在底盘上、转子带着云台转，所以它的多圈角度在机械上就「必然是」$\theta$。**
> 这个量精确、不漂，但**只是"差"，不是"绝对朝向"**。

**⇒ 这是整套系统的信息基础：**
- 编码器给 $\theta$（精确的相对量）
- IMU 给 $\psi_g$（有漂移的绝对量）
- **两者相减，才能得到 $\psi_c$（底盘的世界朝向）**

## 二、小陀螺直线行走

### 2.1 问题：为什么自转会让"直行"变成"画圈"

操作者推"前进"，意图是"**朝某个方向**走"。但底盘在自转，车头方向一直在变。

```
底盘自转 ω
    ↓
车头方向以 ω 的速率旋转
    ↓
如果把"前进"直接理解成"沿车头走"
    ↓
速度矢量的方向也在旋转
    ↓
轨迹是一个圆（半径 r = v / ω）  ✗
```

**⇒ 所以必须做「参考系转换」。**

### 2.2 航向补偿的数学推导

**遥控输入：** 操作者的杆量 $(v_x^{g}, v_y^{g})$ 是**云台系**的速度意图
> 推前进 = "朝**云台指向**的方向走" —— 这符合操作直觉（用云台瞄准，往瞄准方向跑）

**云台系基向量在车体系中的表示：**

云台前方在车体系里的角度就是 $\theta$，所以：

$$e_x^{(g)} = \begin{pmatrix}\cos\theta\\ \sin\theta\end{pmatrix}, \qquad
e_y^{(g)} = \begin{pmatrix}-\sin\theta\\ \cos\theta\end{pmatrix}$$

**把云台系速度转到车体系**（同一个物理向量，换个坐标表示）：

$$\vec{v} = v_x^{g}\,e_x^{(g)} + v_y^{g}\,e_y^{(g)}$$

$$\boxed{
\begin{aligned}
v_x^{b} &= v_x^{g}\cos\theta - v_y^{g}\sin\theta\\
v_y^{b} &= v_x^{g}\sin\theta + v_y^{g}\cos\theta
\end{aligned}}$$

**⇒ 这就是 `chassis_control.c` 里的那两行**：

```c
vx_body = vx * cos_t - vy * sin_t;
vy_body = vx * sin_t + vy * cos_t;
```

### 2.3 ⭐⭐ 关键前提：云台必须锁住世界方向

**上面的公式对任意 $\theta$ 都成立 —— 所以问题不在公式，在于 $\theta$ 能不能正确反映底盘朝向的变化。**

#### 情况 A：云台锁住世界方向（正确）

$$\psi_g \equiv \psi_{g0} \ (\text{常数}) \quad\Longrightarrow\quad \theta = \psi_{g0} - \psi_c$$

**⇒ $\theta$ 和 $\psi_c$ 一一对应（只差一个常数）。**

**⇒ 用 $\theta$ 做补偿 完全等价于 用 $\psi_c$ 做补偿**

**⇒ 车沿【世界系固定方向】走直线** ✅

```
       世界方向（云台锁死，不动）
              ↑
              │  vx_g（推前进的方向，恒定）
              │
         ┌────┴────┐
         │  云台   │  ← 锁住世界方向
         └────┬────┘
              │ θ 随底盘自转而变化
         ┌────┴────┐
         │  底盘   │  ← 自转 ω
         └─────────┘
              ↓
       车体系速度被实时反向旋转 → 实际轨迹是直线 ✅
```

#### 情况 B：云台跟着底盘转（当前的实现）

$$\theta \equiv 0$$

**⇒ 补偿公式退化为恒等变换：**

$$v_x^{b} = v_x^{g}, \qquad v_y^{b} = v_y^{g}$$

**⇒ 车体系速度 = 遥控给的云台系速度，而云台系也在跟着底盘转**

**⇒ 速度方向跟着车头转 → 画圈** ✗

```
底盘自转 ω = 4 rad/s，前进 v = 1 m/s
        ⇒ 轨迹半径 r = v/ω = 0.25 m
        ⇒ 车在画一个直径 50 cm 的圈，根本走不出去
```

### 2.4 完整数据流（正确版）

```
        ┌──────────────┐
        │  MPU6500 IMU │  ψ_g（世界朝向，会漂）
        └──────┬───────┘
               │
               ▼
     ┌─────────────────────┐
     │  云台 yaw 环 @1kHz  │  反馈 = ψ_g
     │  （锁世界方向）      │  目标 = 上电对齐时的朝向 / 遥控给定的绝对角
     └──────────┬──────────┘
                │ 输出 → GM6020
                ▼
          云台锁住世界方向 ✅
                │
                │  云台相对底盘角 θ
                │  （GM6020 绝对编码器）
                ▼
     ┌─────────────────────┐
     │  底盘航向补偿 @1kHz │  vx_b/vy_b = R(θ) · (vx_g, vy_g)
     └──────────┬──────────┘
                ▼
        底盘沿世界直线行走 ✅
```

## 三、跟随模式

### 3.1 语义

**"底盘跟随云台"** = 车头自动转到**云台指向的方向**。

**⇒ 数学目标：$\theta \to 0$**（云台相对底盘的角度归零 = 车头对准云台）

### 3.2 数学

误差 $e = \theta - 0 = \theta$

$$\omega = K_p \cdot \theta \quad (\text{限幅到} \pm \omega_{max})$$

**符号验证：**

| 情形 | $\theta$ | 输出 $\omega$ | 底盘动作 | 效果 |
|---|---|---|---|---|
| 云台偏左 | $> 0$ | $> 0$ | **逆时针**转 | 车头追上云台，$\theta \to 0$ ✅ |
| 云台偏右 | $< 0$ | $< 0$ | **顺时针**转 | 同上 ✅ |

**⇒ 负反馈，收敛** ✅

**代码实现：**

```c
PID_Set_Target(&s_heading_pid, Heading());          /* target = θ */
omega = PID_Calculate(&s_heading_pid, 0.0f, 0.0f);  /* fdb = 0 → error = θ */
```

### 3.3 ⚠️ 前提：云台环不能和它抢同一个量

**跟随环控的是 $\theta$，所以云台环就**不能**再去控 $\theta$。**

| 云台环的类型 | 控制量 | 和跟随环冲突？ |
|---|---|---|
| **锁世界方向**（$\psi_g = 常数$）| $\psi_g$ | ✅ **不冲突**（各控各的）|
| **锁相对底盘**（$\theta = 0$）| $\theta$ | ❌ **冲突！两个环抢同一个量** |

**冲突时会发生什么：**

```
底盘跟随环：把 θ 拉到 0
云台环：    把 θ 拉到 target_yaw
        ↓
两个环互相追
        ↓
θ 永远不收敛 → 底盘持续自转，云台持续反向追
        ↓
表现为【原地小陀螺，停不下来】  ✗
```

## 四、⭐ 三个环的完整分工

| # | 控制环 | 控制量 | 反馈来源 | 目标 | 输出 |
|---|---|---|---|---|---|
| **①** | **云台 yaw 环** | $\psi_g$（世界朝向）| **MPU6500 IMU** | 上电对齐朝向 / 遥控绝对角 | GM6020 电流 |
| **②** | **底盘航向补偿** | — | **GM6020 编码器 $\theta$** | 把云台系速度转到车体系 | $v_x^b, v_y^b$ |
| **③** | **底盘跟随环** | $\theta$（相对角）| **GM6020 编码器** | $\theta \to 0$ | 底盘 $\omega$ |

**⇒ 三个环用三个不同的物理量，互不冲突** ✅

```
                    ┌────────────────────────────────┐
   MPU6500 ────────▶│ ① 云台 yaw 环（锁世界方向 ψ_g）│───▶ GM6020
                    └────────────────┬───────────────┘
                                     │
                                     │ GM6020 绝对编码器
                                     │ θ = 云台相对底盘角
                                     ▼
              ┌──────────────────────┴──────────────────────┐
              ▼                                             ▼
   ┌──────────────────────┐                   ┌──────────────────────┐
   │ ② 航向补偿            │                   │ ③ 跟随环              │
   │    v_b = R(θ)·v_g     │                   │    ω = Kp·(θ → 0)     │
   │  （小陀螺走直线）      │                   │  （底盘跟随云台）      │
   └──────────┬───────────┘                   └──────────┬───────────┘
              ▼                                          ▼
        逆解 → 4 轮 → CAN ────────────────────────────────┘
```

## 五、两种模式的差异

| | **小陀螺模式** | **跟随模式** |
|---|---|---|
| **云台环（①）** | 锁世界方向 | 锁世界方向（操作者可用遥控改朝向）|
| **航向补偿（②）** | ✅ 启用 | ✅ 启用 |
| **底盘 $\omega$（③）** | **恒定** $\omega = \pm\omega_{spin}$ | **PID 输出** $\omega = K_p\theta$（把 $\theta$ 拉到 0）|
| **底盘行为** | 匀速自转 + 沿世界直线行进 | 车头自动对准云台 |
| **$\theta$ 的变化** | 持续单调变化（底盘在转）| 收敛到 0 |
| **共同前提** | ⭐ **云台必须锁住世界方向** | ⭐ **同上** |

## 六、⚠️ 当前实现的缺口

### 缺口：云台环用错了反馈源

**现在的 `Gimbal_Update()`：**

```c
gimbal->yaw = Gimbal_Get_Yaw(gimbal);          /* ← θ（编码器，相对底盘）*/
const float error = Gimbal_Wrap180(gimbal->target_yaw - gimbal->yaw);
gimbal->yaw_motor->Set_Motor_State(gimbal->yaw_motor, cur_angle + error * DIR);
```

**⇒ 它控的是 $\theta$，不是 $\psi_g$。**

**由此产生的两个必然故障：**

| # | 故障 | 机制 |
|---|---|---|
| **①** | **小陀螺走不了直线**（变成画圈）| 云台跟着底盘转 → $\theta \equiv 0$ → 补偿退化成恒等变换 |
| **②** | **跟随变成原地小陀螺** | 云台环和跟随环都在控 $\theta$ → 互相追、永不收敛 |

**⇒ 修复方向：把云台环的反馈从「编码器 $\theta$」换成「IMU $\psi_g$」。**

### 换完之后要注意的两个连带问题

| 问题 | 说明 | 处理思路 |
|---|---|---|
| **IMU 的 yaw 会漂** | 无磁力计，纯陀螺积分（温漂是主因）| ① 短时间（几秒~几十秒）漂移很小，够用<br>② 或做「编码器 + IMU 互补滤波」：编码器给低频、IMU 给高频 |
| **换完之后 $\theta$ 还能给底盘用吗** | ✅ **能，而且更对了** | 它仍然是"云台相对底盘角"，正是航向补偿要的量 |

## 七、常见故障对照表

| 现象 | 可能原因 | 检查 |
|---|---|---|
| **小陀螺画圈、走不了直线** | 云台没锁世界方向（$\theta \equiv 0$）| 看 `gyaw` 是否恒贴 0 |
| **跟随模式原地自转不停** | 云台环和跟随环抢 $\theta$ | 同上；或 `GIMBAL_YAW_DIR` 反了 |
| **云台越跑越远、抖动、发散** | ⭐ **`GIMBAL_YAW_DIR` 符号反了**（正反馈）| 手推云台松手，看回不回位 |
| **上电云台猛转一下** | 零点没对齐 | 检查首次对齐逻辑 |
| **云台完全不动** | 反馈没通（CAN / 供电）| 看 `user_gimbal_yaw_motor.rx_count` 涨不涨 |
| **云台被撞后车跑偏** | $\theta$ 被外力改变 | 云台电机扭矩不足 / 加变化率限幅 |

## 八、一句话总结

> **小陀螺走直线 = 云台锁住世界方向 + 用编码器 $\theta$ 做航向补偿。**
> **跟随 = 云台锁住世界方向 + 用同一个 $\theta$ 把底盘拉到 $\theta \to 0$。**
>
> **两者的共同前提都是「云台锁世界方向」—— 这一条由云台 yaw 环用 IMU（$\psi_g$）做反馈来实现。**
>
> **三个环各控一个量：云台环控 $\psi_g$、航向补偿用 $\theta$、跟随环控 $\theta$ —— 互不冲突。**
> **当前实现里云台环也在控 $\theta$，所以既走不了直线，跟随也变成了原地自转。**
