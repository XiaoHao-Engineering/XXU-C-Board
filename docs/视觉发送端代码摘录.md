## 1. 物理层与参数

### 1.1 串口

| 项目 | 值 | 备注 |
|---|---|---|
| 接口 | **USART1** | 见 `Core/Src/main.c` L223–L224：`UART_Init(&user_vision_uart, &huart1);` |
| MCU 发送脚 TX | **PA9** | 接视觉侧 RX |
| MCU 接收脚 RX | **PB7** | 接视觉侧 TX |
| 波特率 | **115200** | |
| 数据格式 | **8N1**（8 数据位 / 无校验 / 1 停止位） | `UART_WORDLENGTH_8B` + `UART_PARITY_NONE` + `UART_STOPBITS_1` |
| 硬件流控 | 无 | 不要接 RTS/CTS，也不需要 |
| 电平 | 3.3 V TTL | **必须共地**（GND 一定要连） |

> `Core/Src/usart.c` L48–L55 的实际配置：`BaudRate = 115200`、`WordLength = UART_WORDLENGTH_8B`、`StopBits = UART_STOPBITS_1`、`Parity = UART_PARITY_NONE`、`Mode = UART_MODE_TX_RX`、`HwFlowCtl = UART_HWCONTROL_NONE`。

### 1.2 时序

| 项目 | 值 | 说明 |
|---|---|---|
| 发送周期 | **10 ms（100 Hz）** | 宏 `VISION_TX_PERIOD_MS` |
| 单帧线上时间 | 43 × 10 bit / 115200 ≈ **3.73 ms** | 剩余 6.27 ms 空闲 |
| 占用带宽 | 43 B / 10 ms = **4.3 kB/s**，约 115200 上限（11.52 kB/s）的 **37%** | 余量充足 |
| 实际帧率 | "**最快** 100 Hz" | 发送挂在**主循环**里按 `HAL_GetTick()` 自计时；主循环忙时可能略低于 100 Hz，但**不会高于** 100 Hz。请勿依赖"严格等间隔"。 |

### 1.3 帧格式（电控 → 视觉）

| 项目 | 值 |
|---|---|
| 帧长 | **43 字节**（定长，无长度字段，无转义，无字节填充） |
| 帧头 | **`'A' 'A'` = 字节 `0x41 0x41`** |
| 字节序 | **小端（little-endian）**，float 为 **IEEE-754 单精度（float32）** |
| 校验 | **CRC-16/MODBUS**，覆盖**前 41 字节**（偏移 0–40），结果以小端放在**最后 2 字节**（偏移 41–42） |
| 填充 | **无**（结构体用 `__attribute__((packed))`，线上布局 = 内存布局） |

> ### ⚠️ 帧头是最容易搞错的一点
> 帧头是**两个 ASCII 字符 `'A'`**，也就是两个字节 `0x41 0x41`，
> **不是**单字节 `0xAA`，**不是** `0xAAAA`，**不是** `0xA5`。
> 在串口助手的 HEX 视图里要按 `41 41` 去找；在文本视图里它看起来是 `AA`（两个字母 A），这是命名遗留。
> 源码注释原文（`user_vision.h` L33–L36）：
>
> ```c
> #define VISION_FRAME_HEAD        "AA"    /* ⚠️ 帧头是【两个 ASCII 字符 A A】= 字节 41 41，
>                                                  不是十六进制的单字节 0xAA！
>                                                  在串口助手 HEX 里要按 41 41 找。
>                                                  （命名沿用参考工程，RingBuffer 取帧按此串搜索）*/
> ```

### 1.4 CRC 参数（必须逐位一致，否则每包都是坏帧）

| 参数 | 值 |
|---|---|
| 算法名 | **CRC-16/MODBUS** |
| 初值 init | `0xFFFF` |
| 多项式 | `0x8005`，**反射形式 0xA001**（右移算法） |
| 输入反射 / 输出反射 | 是 / 是（代码就是这个"右移 ^ 0xA001"形式） |
| 结果异或 | **无**（`xorout = 0x0000`） |
| 覆盖范围（发送方向） | 结构体**前 41 字节**（偏移 0–40） |
| 覆盖范围（接收方向） | 结构体**前 27 字节**（偏移 0–26，共 29 字节帧） |
| 校验值字节序 | **小端**：低字节在前，高字节在后 |

自检向量（拿去做单元测试）：前 41 字节为第 6 节那一帧时，CRC = **`0xA024`**，线上两字节是 **`24 A0`**。

### 1.5 接收方向（视觉 → 电控）的约定

| 项目 | 值 |
|---|---|
| 帧长 | **29 字节** |
| 帧头 | 同样 **`0x41 0x41`** |
| 字节序 / 类型 | 小端 / float32，packed |
| CRC | CRC-16/MODBUS，覆盖**前 27 字节**，小端放在最后 2 字节（偏移 27–28） |
| 字段 | `mode`(u8) / `yaw` / `yaw_vel` / `yaw_acc` / `pitch` / `pitch_vel` / `pitch_acc`（6 个 float） |
| **角度单位** | **弧度、弧度/秒、弧度/秒²**（不是度！见第 2 节 `VISION_ANGLE_UNIT_RAD`） |
| 离线判定 | 连续 **50 ms**（`VISION_OFFLINE_MS`）没收到**CRC 正确**的帧 → 判视觉离线 |
| 频率期望 | 100 Hz（我们每 10 ms 收一次；29 B 在 115200 下只要 2.52 ms，发得出来） |

### 1.6 上电瞬间的 ASCII 噪声（解析器要能跳过）

USART1 在初始化阶段会先被用来打几行**阻塞式 ASCII 文本**（板级自检），之后才开始周期发二进制帧。
所以视觉侧**不能假设字节流是从帧头开始的**，必须先搜 `41 41` 再取 43 字节（并且做 CRC 校验确认）。

```c
231:         static const char id_uart1[] = "\r\n=== this port is USART1 ===\r\n";
234:         HAL_UART_Transmit(&huart1, (uint8_t*)id_uart1, sizeof(id_uart1) - 1, 100);
```

> 除了上面那行口名标识，上电期间还会再打出 **4~6 行** ASCII：
>
> - `"SERIALPLOT OK\r\n"`（`Core/Src/main.c` L214–L215）
> - `"[BOOT] ..."` 系列，**每过一个初始化阶段一行**（例如 `"[BOOT] M2 IMU + attitude OK"`、
>   `"[BOOT] M4 chassis_control OK - plot should start"`，见 L200 / L284 / L288–L289）。
>   这个 `BOOT_TRACE` 宏（L83–L87）同时往 **USART6 和 USART1** 各发一份：
>
> ```c
> #define BOOT_TRACE(tag) do {                                        \
>     static const char _bt[] = "\r\n[BOOT] " tag "\r\n";              \
>     HAL_UART_Transmit(&huart6, (uint8_t*)_bt, sizeof(_bt) - 1, 200); \
>     HAL_UART_Transmit(&huart1, (uint8_t*)_bt, sizeof(_bt) - 1, 200); \
> } while (0)
> ```
>
> 这些行都是纯 ASCII（`0x20`–`0x7E` + CR/LF），**不含** `41 41`，
> 所以"按帧头搜索 + CRC 校验"就能自然过滤掉，不需要特殊处理。
> 它们只在**上电初始化的几十毫秒内**出现，之后 USART1 上就只有 43 字节的二进制帧了。

## 3. 字段表（MCU → 视觉，43 字节，重点：给对拍用）

### 3.1 总表

> **解析前提**：小端、float32、packed、无填充。
> `q[]` 从**偏移 3** 开始 —— 是**奇数偏移**，也就是说 float 在线上**不是 4 字节对齐**的。
> 请不要用"带对齐的结构体直接强转"这种方式解析（C/C# 默认对齐会插 1 字节 padding、后面全错），
> 请按字节 + 小端读取（Python `struct` / numpy `frombuffer(offset=..)` 都没问题）。

| 偏移 (dec) | 偏移 (hex) | 字段 | C 类型 | 字节数 | 单位 | 含义 | 当前取值条件 |
|---:|---|---|---|---:|---|---|---|
| 0 | 0x00 | `head[0]` | `uint8` | 1 | — | 帧头第 1 字节 = `'A'` = `0x41` | 固定 |
| 1 | 0x01 | `head[1]` | `uint8` | 1 | — | 帧头第 2 字节 = `'A'` = `0x41` | 固定 |
| 2 | 0x02 | `mode` | `uint8` | 1 | 枚举 | 工作模式，见 3.2 | 由操作手"自瞄使能开关"决定，只发 0 / 1 |
| 3 | 0x03 | `q[0]` | `float` | 4 | — | 四元数 **w**（实部） | EKF 输出，绕世界 Z 旋转 `-bias_accum` 之后 |
| 7 | 0x07 | `q[1]` | `float` | 4 | — | 四元数 **x** | 同上 |
| 11 | 0x0B | `q[2]` | `float` | 4 | — | 四元数 **y** | 同上 |
| 15 | 0x0F | `q[3]` | `float` | 4 | — | 四元数 **z** | 同上 |
| 19 | 0x13 | `yaw` | `float` | 4 | **rad** | 云台当前**世界系** yaw 角，±π（等价 ±180°） | `Wrap180(imu_yaw − bias_accum) × π/180` |
| 23 | 0x17 | `yaw_vel` | `float` | 4 | **rad/s** | 世界系 yaw 角速度 | `user_attitude.yaw_rate × π/180`（IMU 陀螺） |
| 27 | 0x1B | `pitch` | `float` | 4 | **rad** | IMU 俯仰角（见 3.4，**不是**枪管关节角） | `user_attitude.qe_roll × π/180` |
| 31 | 0x1F | `pitch_vel` | `float` | 4 | **rad/s** | pitch 轴电机转速换来的角速度 | `pitch_speed(RPM) × 6 × π/180` |
| 35 | 0x23 | `bullet_speed` | `float` | 4 | **m/s** | 当前弹速（给视觉算弹道） | `friction_rpm_filt × 0.10471976 × 0.03`，摩擦轮停时为 **0** |
| 39 | 0x27 | `bullet_count` | `uint16` | 2 | 发 | 剩余弹量 | **硬编码 0**（未接裁判系统） |
| 41 | 0x29 | `crc16` | `uint16` | 2 | — | CRC-16/MODBUS，覆盖偏移 0–40，**小端** | 每帧发送前现算 |

合计：2 + 1 + 16 + 16 + 4 + 2 + 2 = **43 字节**。

### 3.2 `mode`：0 = 空闲 / 1 = 控制 / 2 = 控制+开火

| 值 | 宏 | 含义 | 电控希望你们怎么做 | 当前是否会出现 |
|---:|---|---|---|---|
| **0** | `VISION_TX_MODE_IDLE` | **空闲，不控制** | 立刻**停止**给控制量（我们这边也会回摇杆） | ✅ 会出现（未开自瞄） |
| **1** | `VISION_TX_MODE_AUTOAIM` | **自瞄，可以控制** | 开始/继续输出目标角 | ✅ 会出现（开自瞄） |
| **2** | （源码宏名 `VISION_TX_MODE_SMALL_BUFF`，"小符"） | 约定语义：**控制 + 开火** | 目前**不会出现**，请按"预留"处理 | ❌ **当前代码从不发送** |
| 3 | `VISION_TX_MODE_BIG_BUFF` | 宏名"大符" | 不存在于任何协议约定中 | ❌ 从不发送 |

**当前实际只发 0 和 1**，由 `gimbal.c` 里的这一行决定（`gimbal.c` L435–L436，见第 5 节）：

```c
    Vision_Set_Tx_Mode(&user_vision,
                       (gimbal->yaw_auto > 0.5f) ? VISION_TX_MODE_AUTOAIM : VISION_TX_MODE_IDLE);
```

也就是说：**`mode` 反映的是操作手有没有把"自瞄"开关打开**，而不是"视觉现在能不能控制"。
它是我方和你们的**握手信号**：只有先看到 `mode=1`，你们才开始发 `mode=1` 的控制包。
`mode=2`（开火）目前**没有实现**，将来要开火会另行通知并改这个文件。

> ⚠️ 注意 `2` 的两层含义不要混：**电控→视觉** 的 `mode=2` 是"控制+开火"；**视觉→电控** 的
> `mode=2` 是"请求开火"（`VISION_RX_MODE_CONTROL_AND_FIRE`）。两者方向不同、宏不同名。

### 3.3 `q[4]`：四元数，顺序是 **w, x, y, z**

- 顺序：`q[0]=w`（实部，标量），`q[1]=x`，`q[2]=y`，`q[3]=z`。**先 w，不是先 x/y/z！**
  常见错误是 numpy `[x,y,z,w]` 或 scipy `(x,y,z,w)` 的约定，请确认你们的库怎么排。
- 坐标系：**世界系**（Z 轴向上，右手系），表示"机体到世界"的旋转（ZYX 欧拉序反解见 3.7）。
- **单位四元数**，但**不是精确 1**：实机实测 **|q| = 0.9983**（约 0.998），因为 EKF 有数值漂移。
  **请在使用前自己归一化**（`q /= norm(q)`），不要假设 `|q| == 1`。
- q 里的 yaw 分量已经和 `yaw` 字段**同一基准**（都扣掉了零偏 `-bias_accum`），详见第 5.2 节。
- 视觉不用 q 也完全可以只用 `yaw/pitch`；但如果要做完整三维变换（比如算目标在相机系的朝向），用 q 更准。

### 3.4 `pitch` 到底是"哪个 pitch"（重要，容易对不上）

`pitch` 字段取自 **`user_attitude.qe_roll`**（EKF 的 **Roll** 角），而不是 `qe_pitch`。
原因（源码注释原文，`gimbal.c` L420–L430）：

```c
    /* ★ pitch 字段：见 user_vision.h 里 VISION_PITCH_USE_IMU_ONLY 的说明。
       本车 IMU 在 yaw 框架上 -> 枪口世界仰角 = IMU俯仰 + 编码器俯仰 */
#if VISION_PITCH_USE_IMU_ONLY
    /* ★ 与参考工程一致：参考的 Gimbal.IMU_Gimbal.Get_Angle_Pitch() 返回 Data_Euler.pitch,
       而 dvc_bmi088.cpp:524-527 写明"QEKF_INS.Roll 实际是绕 Y 轴的俯仰角"
       -> Data_Euler.pitch = QEKF_INS.Roll。所以发给视觉的 pitch 要用 qe_roll 而不是 qe_pitch。
       实测两个独立样本都验证了这一点：包内 pitch ≈ 四元数解出的 roll。 */
    const float tx_pitch = user_attitude.qe_roll;
#else
    const float tx_pitch = user_attitude.qe_pitch + gimbal->pitch;
#endif
```

用一句话说清：
1. 我们的 IMU 焊在云台的 **yaw 框架**（yaw/pitch 转轴连接处），它**看不到枪管自己绕 pitch 轴的俯仰**。
2. 这块 IMU 的 EKF 输出的 `Roll` 在**物理上就是"绕 Y 轴（水平横向轴）的俯仰"**，
   名字叫 Roll、实际是 Pitch —— 这是参考工程沿用的命名习惯。
3. 当前 `VISION_PITCH_USE_IMU_ONLY = 1`，所以包里 `pitch` = **只有 IMU 的俯仰角**，
   **不含**枪管相对 yaw 框架的编码器角度。
4. 因此包里 `pitch` 的语义是：**"云台 yaw 框架在世界系里的俯仰/倾斜角"**（大致等于底盘俯仰 + 一点安装倾斜），
   而**不是**"枪口相对水平面的仰角"，也**不是**"pitch 电机关节角"。

> ⚠️ 这里存在一个**语义不对称**，需要和你们确认（第 7 节问题 2）：
> 我们**发给**你们的 `pitch` 是"IMU 的世界系俯仰"；
> 我们**期望从**你们**收到**的 `pitch` 却被当成"pitch 关节角目标"直接进控制（`gimbal.c` L1040）。
> 两边定义必须对齐，否则表现就是"越近越上抬/下压反了"（见附录 A 第 4 条）。

### 3.5 `yaw` / `yaw_vel` / `pitch` / `pitch_vel` 单位

**全部是弧度制**（因为 `VISION_ANGLE_UNIT_RAD = 1`）：

| 字段 | 单位 | 量程/典型值 | 换算 |
|---|---|---|---|
| `yaw` | rad | ±π（±3.1416），典型 ±0.5 | 度 = rad × 57.29578 |
| `yaw_vel` | rad/s | 典型 ±5 | 度/秒 = rad/s × 57.29578 |
| `pitch` | rad | 实测约 +0.18（≈ +10.5°） | 度 = rad × 57.29578 |
| `pitch_vel` | rad/s | 典型 ±1 | 度/秒 = rad/s × 57.29578 |

- `yaw` 是 **Wrap 到 ±180°**（±π）后的值，**不累积**、不会变成 ±360° 以上。跨 ±π 时是跳变的（+π → −π），
  你们做差时**必须**先 wrap 到 ±180°，否则会出现 360° 的假误差。
- `yaw_vel` 是**世界系**角速度（IMU 陀螺，已做俯仰投影补偿），单位 rad/s。
- `pitch_vel` 取自 pitch 电机的**反馈转速**（RPM × 6 换成 deg/s），不是 IMU 量，
  因此它反映"枪管相对 yaw 框架的转动速度"，轴向上和 `pitch`（IMU 世界俯仰）**不完全同源**，
  做前馈时请按"关节角速度"来理解。

### 3.6 `bullet_speed` / `bullet_count`

**`bullet_speed`（float，m/s）**


```
bullet_speed[m/s] = 摩擦轮实测转速[RPM] × 0.10471976 (RPM→rad/s) × 0.03 (系数)

```

| 摩擦轮 RPM | bullet_speed |
|---:|---:|
| 0（摩擦轮停） | **0.000 m/s** |
| 1000 | 3.142 m/s |
| 3000 | 9.425 m/s |
| 6000 | 18.850 m/s |

- `friction_rpm_filt` 是**两个摩擦轮实测转速绝对值平均后再 FIR 滤波**的值（单位 RPM）。
  摩擦轮没开（射手状态机 STOP）→ 实测转速 0 → **`bullet_speed` 就是 0**，不会是 5.0、不会是 NaN。
- 系数 `0.03` 是从参考工程抄的，**没有实测标定**。真实弹速请以你们测的为准，
  需要标定时告诉我们一声，我们改这个宏即可（协议不变）。

**`bullet_count`（uint16，发）**

- 目前**硬编码 `0`**，没有实现。真实弹量要接裁判系统，本车没接。
- 请不要用 `bullet_count == 0` 判断"没弹了"——那会让你们一直认为没弹。

### 3.8 参考解析代码（Python，**示例，不是摘录**）

```python
import struct

TX_FMT  = '<2sB4f4ffHH'      # 2+1+16+16+4+2+2 = 43，'<' 表示小端且不填充
TX_SIZE = 43
CRC_INIT, CRC_POLY = 0xFFFF, 0xA001

def crc16_modbus(data: bytes) -> int:
    crc = CRC_INIT
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ CRC_POLY if (crc & 1) else (crc >> 1)
    return crc & 0xFFFF

def parse(buf: bytes):
    # buf 必须是恰好 43 字节，且 buf[0:2] == b'AA'
    (head, mode, w, x, y, z, yaw, yaw_vel,
     pitch, pitch_vel, bullet_speed, bullet_count, crc) = struct.unpack(TX_FMT, buf)
    ok = (crc16_modbus(buf[:41]) == crc)      # CRC 覆盖前 41 字节
    n  = (w*w + x*x + y*y + z*z) ** 0.5
    return dict(head=head, mode=mode, q=(w/n, x/n, y/n, z/n), q_norm=n,
                yaw=yaw, yaw_vel=yaw_vel, pitch=pitch, pitch_vel=pitch_vel,
                bullet_speed=bullet_speed, bullet_count=bullet_count,
                crc=crc, crc_ok=ok)
```

### 4.1 `Vision_CRC16()` 完整实现

**源码位置：`User_Drives/User_Peripheral/Src/user_vision.c` L16–L37**

```c
/* CRC-16/MODBUS：init 0xFFFF、反射、poly 0xA001。
   ★ 必须和视觉侧逐位一致，否则每一包都会被判为坏帧（表现为"永远离线"）。*/
uint16_t Vision_CRC16(const uint8_t* data, uint16_t len) {
    uint16_t crc = 0xFFFFU;

    if (data == NULL) {
        return crc;
    }

    for (uint16_t i = 0; i < len; i++) {
        crc ^= (uint16_t)data[i];
        for (uint8_t j = 0; j < 8U; j++) {
            if (crc & 0x0001U) {
                crc = (uint16_t)((crc >> 1U) ^ 0xA001U);
            } else {
                crc >>= 1U;
            }
        }
    }

    return crc;
}
```

> 注意：`Vision_CRC16(NULL, len)` 返回 `0xFFFF`（错误保护），正常组包不会走到这条分支。

### 4.2 发送节拍：`Vision_LoopHandle()`

**源码位置：`user_vision.c` L39–L52**

```c
/* ★★ 视觉发送改由【主循环】驱动（不再挂 1ms SysTick 任务）：
   这样 UART 收发完全不占 1ms 中断预算，主循环慢一点只是发送率略降，不影响功能。
   发送周期由 HAL_GetTick() 自计时限制为 VISION_TX_PERIOD_MS（默认 10ms=100Hz）。
   注：这里的 HAL_GetTick 在主循环里是正常推进的（不会像在 ISR 里那样被冻住）。*/
static uint32_t s_vision_last_tx_ms = 0U;

static void Vision_LoopHandle(void) {
    const uint32_t now = HAL_GetTick();
    if ((uint32_t)(now - s_vision_last_tx_ms) < VISION_TX_PERIOD_MS) {
        return;                     /* 还没到下一个发送周期，直接返回 */
    }
    s_vision_last_tx_ms = now;
    Vision_Update(&user_vision);
}
```

> 这就是"**10 ms 一帧，100 Hz**"的实现。它跑在主循环里（不是定时器中断），
> 所以实际周期是"**≥ 10 ms**"，主循环很忙时会略微变长（可能 11–12 ms），但绝不会更快。
> 视觉侧做时间戳插值/滤波时请按"收到的实际时间"算，别写死 10.000 ms。

### 4.3 组包 + 算 CRC + 发送：`Vision_Update()`

**源码位置：`user_vision.c` L172–L191**（本函数同时负责离线判定与发包）

```c
/* 周期任务：发包 + 离线判定 */
static void Vision_Update(void* arg) {
    VISION_DRIVES* vision = (VISION_DRIVES*)arg;

    /* 离线判定：超时只置标志，不动数据（目标角由应用层决定"保持"还是"回手动"）*/
    if (vision->is_online != 0
        && (HAL_GetTick() - vision->last_rx_ms) > VISION_OFFLINE_MS) {
        vision->is_online = 0;
        vision->timeout_count++;
        vision->frame_count_f = (float)vision->frame_count;
        vision->online_f = (float)vision->is_online;   /* 镜像跟着掉 0，绘图才不会一直显示"在线" */
    }

    /* 组包并发出：CRC 覆盖除最后 2 字节以外的全部内容 */
    vision->tx_packet.crc16 = Vision_CRC16((const uint8_t*)&vision->tx_packet,
                                           VISION_TX_PACKET_SIZE - 2U);
    UART_Send_Data(vision->uart, (const char*)&vision->tx_packet, VISION_TX_PACKET_SIZE);
    vision->tx_count++;
    vision->tx_count_f = (float)vision->tx_count;
}
```

关键 3 行（就是"算 CRC + 发出去"）：

```c
    vision->tx_packet.crc16 = Vision_CRC16((const uint8_t*)&vision->tx_packet,
                                           VISION_TX_PACKET_SIZE - 2U);
    UART_Send_Data(vision->uart, (const char*)&vision->tx_packet, VISION_TX_PACKET_SIZE);
    vision->tx_count++;
```

> - `VISION_TX_PACKET_SIZE - 2U` = **41** → CRC 覆盖偏移 0–40，不含 crc16 自身。
> - `UART_Send_Data` 是"拷进发送队列 + DMA 异步发出"，**不阻塞**；
> - **每帧都重算 CRC**，不缓存。所以只要 `tx_packet` 被改过，下一帧的 CRC 一定跟着变。

### 4.6 收包与校验（视觉 → 电控，供参考）

补充说明：
- `* 6.0f` 的来历：**1 RPM = 6 °/s**（360°/60s）。`pitch_speed` 是 GM6020 的转子转速（RPM），直驱 1:1。
- `Gimbal_Wrap180()` 把角度折到 **[-180, +180)**，实现（`gimbal.c` L1256–L1267）：

```c
static float Gimbal_Wrap180(float deg) {
    /* 先用整数除法一次折叠到 ±360 以内，再 while 微调：云台一直转，deg 可能几万度，纯 while 太慢 */
    deg -= 360.0f * (float)((int32_t)(deg / 360.0f));

    while (deg >= 180.0f) {
        deg -= 360.0f;
    }
    while (deg < -180.0f) {
        deg += 360.0f;
    }
    return deg;
}
```

- `bias_accum` 是"陀螺零偏在线跟踪"累积出来的角度（单位 deg）：摇杆居中、编码器判断云台没动时，
  认为此刻测到的 `yaw_rate` 就是零偏，低通后积分成 `bias_accum`，再从 `imu_yaw` 里减掉。
  **这是为了让发给你们的世界 yaw 和闭环用的反馈是同一个基准、漂移速度一致。**

### 5.2 q 为什么被 `-bias_accum` 旋转（摘录 + 说明）

上面的 `{ ... }` 块：

```c
        const float b_half = 0.5f * Gimbal_Wrap180(gimbal->bias_accum) * GIMBAL_DEG2RAD;
        const float qc = cosf(b_half);
        const float qs = sinf(b_half);
        const float qw0 = user_attitude.qe_q[0];
        const float qx0 = user_attitude.qe_q[1];
        const float qy0 = user_attitude.qe_q[2];
        const float qz0 = user_attitude.qe_q[3];
        gimbal->tx_qw = qc * qw0 + qs * qz0;
        gimbal->tx_qx = qc * qx0 + qs * qy0;
        gimbal->tx_qy = qc * qy0 - qs * qx0;
        gimbal->tx_qz = qc * qz0 - qs * qw0;
```

数学上就是：`q_out = q_rot ⊗ q_in`，其中 `q_rot = (cos(b/2), 0, 0, -sin(b/2))`
（绕世界 **Z** 轴转 **−b** 度，b = `bias_accum`），`⊗` 为四元数乘法。

**为什么**：原始 `qe_q` 里含着 IMU 未修正的 yaw 零漂；而 `yaw` 字段是**扣掉零偏**的。
如果 q 不跟着转，q 和 yaw **两个字段的坐标系就差一个慢变的 `bias_accum`**，
你们用 q 定世界系就会比用 yaw 漂得更快、两者互相矛盾。
所以填值前把 q 统一旋转 `-bias_accum`，让 **`q` 和 `yaw` 的 yaw 分量严格一致**。
（实测验证：第 6 节那一帧由 q 反解的 yaw = +0.077°，`yaw` 字段 = +0.237°，差 0.16° 属正常误差量级。）

### 5.3 `mode` 为什么看 `yaw_auto` 而不是 `aim_takeover`

源码注释（原样）：

```c

       这是和视觉的握手 —— 只有先告诉视觉"AUTOAIM"，它才会开始发 mode=1/2 的控制包；
```

也就是说：**我们先把 `mode=1` 发出去，你们才该开始发控制包**。
如果你们等我们"已经在自瞄"（`aim_takeover`，取决于你们的 `mode`）再发控制包，就会双方互等（死锁）。
`aim_takeover` 只有在我们已经在线、收到了你们的 `mode=1` 之后才会置位。

### 6.4 ⚠️ 这一帧的 CRC 对不上是**正常的**，别以为我们算错了

| 项 | 值 |
|---|---|
| 帧里带的 `crc16` | **`0x8DB4`** |
| 按**这 41 字节**重新算出来的 CRC | **`0xA024`**（线上应为 `24 A0`） |
| 两者 | **不一致** |

**原因（务必理解）**：这一帧是**从 MCU 内存里读的快照**，不是串口上抓的。
`crc16` 字段是**上一次真正发包时**（`Vision_Update`）算好写进去的；
而之后 1 kHz 的云台任务还在不停地更新 `q / yaw / yaw_vel / pitch / pitch_vel`，
**在下一次发包把 CRC 重算之前**，内存里就出现了"数据是新的、CRC 是旧的"这种中间状态。

这是在**内存快照**下必然出现的现象，**不代表发出去的帧 CRC 是错的**：

- 真正从 USART1 线上抓的帧，CRC 一定对（因为 `Vision_Update` 是**先算 CRC 再发送**，中间不做别的事）；
- 所以 **请勿用这一帧去判断我们的 CRC 实现对不对**；
- 要验证 CRC 实现，请用 6.2 的字段值反推结构体、按 CRC-16/MODBUS 算前 41 字节，
  应该得到 `0xA024` —— 这个才是我们实现算出来的值（已用独立脚本复算确认）。

> 换句话说：**字段值是可信的（它们就是那一时刻的真实姿态），CRC 是"过期的"。**
> 我们附这一帧的目的是让你们**核对字段偏移、字节序、单位、量级**，不是核对 CRC。

- 建议你们的处理：`if (bullet_speed < 0.1f) 沿用上一次有效弹速 / 或用默认 25 m/s / 或直接不输出目标`。
- 顺便：**`bullet_speed` 里的系数 `0.03` 没标定过**，请把你们实测/仿真用的真实弹速告诉我们，
  我们改宏即可（协议不变）。也请告知你们**期望弹速是 m/s 还是别的小数一位精度**。

## 附录 B：一句话总结（给视觉同学的最短版本）

> USART1、115200 8N1；每 10 ms 一帧 **43 字节**；帧头 **`41 41`**（ASCII 的 `'A''A'`，不是 0xAA）；
> 小端 packed；`head[2] mode q[4](w,x,y,z) yaw yaw_vel pitch pitch_vel bullet_speed bullet_count crc16`；
> **角度的单位全是弧度**；CRC-16/MODBUS（init 0xFFFF / poly 0xA001 反射）算**前 41 字节**、结果**小端**放最后 2 字节；
> `mode` 我们只发 **0（别控制）/ 1（可以控制）**；`bullet_speed` 摩擦轮停时是 **0**；`bullet_count` 固定 **0**。
